问题特征 → 候选工具 → 检查前提

每张卡从上往下读：浅色框是问题特征，带链接的蓝色框是候选工具，底部列出需要检查的前提。箭头表示推理顺序，不保证条件自动成立；同一个问题可以同时需要排序、图、缓存等多种工具。

把候选工具落到真实输入上：例如先从日志中取出某个时间段，再从结果里选出最大的 10 个值。若日志按时间升序，可先用二分定位范围边界；接着用大小为 10 的堆维护 Top-K。两个步骤的前提和成本要分别检查。

基础算法：要全部排好，还是只找一部分？

把 [5,2,3,1,4] 全部排好，可以观察快速排序怎样分组再递归；只找一个边界、一个最大值或最大的 k 个值，则不必总是完整排序。进入基础算法，看快排动图、二分边界与基础模式。

比较 n 个可一致比较的元素；成本对应下列常见实现，平均情况还取决于输入分布
排序时间成本与条件关键动作与稳定性条件
冒泡排序平均 / 最坏 O(n²)；带“本轮无交换就停止”的版本在已有序时最佳 O(n)。相邻逆序就交换；相等时不交换的实现稳定。
选择排序经典版本最佳 / 平均 / 最坏均为 O(n²)。反复选出剩余最小值并交换到前面；经典交换版本通常不稳定。
插入排序平均 / 最坏 O(n²)；已有序时最佳 O(n)，近乎有序时移动通常较少。将当前元素插入有序前缀；只向后移动严格大于它的元素时稳定。
快速排序平均 O(n log n)；连续极不平衡分区时最坏 O(n²)。本页所链接的三路教学版在全相等输入上只需一轮 O(n) 扫描。按基准分区再递归；经典原地交换版通常不稳定。教程的新列表版按输入顺序收集小于、等于、大于三组，保留相等项次序，空间成本也不同。
归并排序常见自顶向下数组版本最佳 / 平均 / 最坏均为 O(n log n)，辅助空间 O(n)。分别排好两半，再合并；相等时先取左侧才能保持稳定。
堆排序完整排序平均 / 最坏 O(n log n)；常见迭代式原地实现辅助空间 O(1)。建堆并反复取堆顶，得到全部有序结果；通常不稳定。

稳定指相同排序键的记录仍保持原来的先后次序，例如同分学生保持报名顺序。这个性质取决于具体实现，不能只靠算法名称判断。新列表快排在平均情况下峰值辅助空间 O(n)，退化时可达 O(n²)，不能套用原地版的空间结论。

Top-K 是另一个目标：若只要 n 个值中最大的 k 个，可用大小为 k 的小顶堆，时间 O(n log k)、空间 O(k)，这里假设 1 ≤ k ≤ n；k=1 可直接 O(n) 扫描。入选的 k 个值还没整体排好，需要有序输出时另加 O(k log k)。这与把全部 n 个值做堆排序不同。

其他基础模式也从输入约束开始：哈希表适合按键查找，双指针适合维护特定的区间或两端关系，栈按后进先出安排处理，队列按先进先出安排处理。它们的具体例子与成本条件见基础页。

数据结构：需要保留哪种关系？

要把 A→B→C→D 反转，关键是保存尚未处理的后继，再重连 next；要找 A 到 E 的最少边数，关键是用队列按层探索。进入数据结构，跟随链表引用与 BFS 队列的变化。

  • 链表：拿到前驱节点后，插入或删除可只改 O(1) 个引用；先寻找该位置仍可能花 O(n)。反转教学例要求无环单链表，会改变原节点的链接。
  • 树与堆：二叉搜索树（BST）按有序关系缩小查找范围，成本取决于树高；二叉堆只保证堆顶优先，不保证整个数组有序。字典树（Trie）沿字符共享前缀，成本还要考虑字符串长度。
  • 图：BFS 的首次发现层数给出无权图的最少边数；深度优先搜索（DFS）先向深处探索，首次找到的路径不保证最短。带权距离、任务依赖与动态连通性分别还需检查边权、是否有环及允许哪些更新。

算法思想：拆分、复用，还是枚举选择？

把 [4,1,3,2] 分半排序后合并、计算爬楼梯走法、选择最多的不重叠区间、生成 [1,2,3] 的排列，看起来都在“分步骤”，但每种步骤的成立理由不同。进入算法思想，对照四种具体过程。

  • 分治：拆成较小的同类问题，递归求解，再合并；要说明递归怎样缩小并终止，以及合并成本。
  • 动态规划：明确定义状态、初始值和转移，按依赖顺序保存并复用子问题答案。重复子问题是复用的线索，还要确认状态包含后续决策所需的信息；DP 可以计数、判断可行性，也可以优化，不能一律只用“最优子结构”解释。
  • 贪心：按规则做选择且不撤销，需要证明当前选择不会妨碍目标。最早结束优先能最大化互不重叠区间的数量；区间有不同收益时，目标改变，原规则就不保证最优。
  • 回溯：选择、递归探索、撤销选择；生成排列时必须恢复路径与使用标记，才能让后续分支从正确状态开始。输出全部结果本身也有成本。

工程算法：省下了什么，又接受了什么限制？

缓存满了淘汰谁？节点扩容后哪些键迁移？一个名字是否值得去真实存储里查？进入工程算法，跟随缓存顺序、哈希路由和位数组的变化。

  • 缓存淘汰：LRU 看最近使用的先后，最不经常使用（LFU）看访问次数。哈希表配双向顺序结构可让 LRU 的 get / put 在哈希与比较成本视为常数、分布正常时通常 O(1)；是否适合负载还需看访问局部性与命中率。
  • 字符串匹配：KMP、Trie、AC 自动机、Rabin–Karp 分别利用匹配前缀、共享前缀、多模式状态、窗口哈希等信息。先说明是单模式、多模式还是前缀查询，再计算预处理、扫描与输出成本。
  • 布隆过滤器：只插入的标准版本中，插入与查询参数、哈希函数一致，状态未损坏且已包含待查数据时，出现 0 可排除已插入；全为 1 仍可能是假阳性，需要查真实存储。不能任意清位删除，也不能独自完成准确去重。
  • 一致性哈希：沿环找键的后继节点，增删节点只改变部分键的归属；不保证负载完全均匀，也不提供复制或故障恢复。Redis Cluster 采用 16384 个哈希槽，扩容迁移槽及数据，不能直接当作一致性哈希环的实例。

AI 时代算法：先比较表示，再解释结果

对于 q=(1,0)，为什么 A=(1,0) 的余弦分数高于 B=(1,1)？给定参数算出预测，是否就完成了训练？注意力如何把多个值混合成一个输出？进入 AI 时代算法，逐项计算相似度、损失与注意力权重。

  • 向量检索：嵌入表示（Embedding）的模型与预处理应兼容；余弦要求同维非零向量。教程对 N 篇 d 维文档精确打分并完整排序，时间 O(Nd + N log N)、辅助空间 O(N)。
  • 近似检索：近似最近邻（ANN）可能漏掉精确 Top-K；HNSW 是其中一种索引方法，Faiss 是提供多种索引的检索库。应以精确结果为基线，同时测召回、延迟与内存。
  • 机器学习与注意力：固定参数的预测和损失计算还不是训练；训练需要更新参数并检验泛化。注意力按分数给值加权，教程只做单查询的教学前向计算，权重不能直接充当严格的因果解释。

学习路线：用能解释的过程检查掌握

先从数组、引用、栈和队列补齐表示问题的能力，再把排序、二分、遍历与状态递推连起来。每次拿一份小输入，手算状态、运行代码，再解释一个会让算法失效的边界；能做到这些，再增加数据规模或换题目。
