Algorithm 01

基础算法：从一组数的变化开始

先看程序正在处理哪一段数据，再看它怎样缩小问题。这一页用排序和二分查找练习这种观察方式，最后认识去重、窗口、栈和队列的用途。

快速排序：先分组，再分别排好

问题：把 [5, 2, 3, 1, 4] 从小到大排列。快速排序每次选一个基准值（pivot），把元素分成小于、等于、大于基准的三组，再用同样的方法排序两侧。本例选择中间位置的元素：下标从 0 开始，5 // 2 = 2，所以第一个基准是 3；它不是先计算出来的中位数。

  1. 扫描一次，分成三组。依次读取 5、2、3、1、4，按与 3 的比较结果加入新列表，得到小于区 [2, 1]、等于区 [3]、大于区 [5, 4]。动图中的移动表示复制到新列表，原输入不变。此时两侧仍然没有排好序。
  2. 递归处理两侧。递归就是让函数用相同方法处理更小的输入。左侧 [2, 1] 的中间位置是下标 1，基准为 1；分出 []、[1]、[2]，返回 [1, 2]。右侧 [5, 4] 的基准为 4；分出 []、[4]、[5]，返回 [4, 5]。空列表和单元素列表直接返回副本，不再分区。
  3. 按顺序拼接。已经排好的左侧 [1, 2]、等于区 [3]、已经排好的右侧 [4, 5] 连接起来，才得到完整结果 [1, 2, 3, 4, 5]。

为什么拼接后有序？分区保证左侧每个值都小于基准，右侧每个值都大于基准；递归又保证这两组内部有序。因此按“左侧 + 等于区 + 右侧”拼接，不会出现前面的数比后面的大。等于区不需要继续排序，也避免重复值在递归中反复参与比较。

def quick_sort(nums):
    if len(nums) <= 1:
        return nums[:]
    pivot = nums[len(nums) // 2]
    less, equal, greater = [], [], []
    for value in nums:
        if value < pivot:
            less.append(value)
        elif value > pivot:
            greater.append(value)
        else:
            equal.append(value)
    return quick_sort(less) + equal + quick_sort(greater)

调用 quick_sort([5, 2, 3, 1, 4]) 返回 [1, 2, 3, 4, 5]。输入应支持一致的大小比较；空列表返回 []，单元素返回同样内容的新列表。

成本按这份代码计算：每次分区扫描当前列表一次。平均时间为 O(n log n)（通常假设输入顺序随机），连续出现极不平衡分区时，最坏为 O(n²)。父调用会保留自己的分区列表，所以平均峰值辅助空间为 O(n)，退化时可达 O(n²)；其中递归栈平均 O(log n)、最坏 O(n)。这是便于理解的新列表版本，不要套用经典原地分区版本的空间或稳定性结论。

同样是排序，解决方式可以不同

  • 归并排序：把输入分成两半，分别排好后，反复取两侧当前较小的元素合并。时间 O(n log n)；常见数组实现需要 O(n) 辅助空间。相等元素先取左侧，才能保留它们原来的先后顺序，这叫稳定排序。例如按分数排序时，同分学生仍按原来的报名顺序排列。链表合并可以调整链接，大文件排序则需要把分段读写成本一起考虑。
  • 完整堆排序：先组织成最大值在顶部的二叉堆，再不断取出最大值放到数组末尾，并修复剩余堆。用于把全部 n 个元素排好，时间 O(n log n)；常见迭代式原地实现的辅助空间 O(1)，通常不稳定。
  • 用大小为 k 的堆找 Top-K：若只要最大的 k 个值，可以维护一个大小不超过 k 的小顶堆，堆顶是当前入选者中最小的值；新值更大才替换它。n 个值的处理时间 O(n log k)，辅助空间 O(k)，这里假设 1 ≤ k ≤ n；k = 1 时可直接线性扫描。堆内的 k 个值还没有整体排好，若要有序输出，另需 O(k log k)。

二分查找：找第一个不小于目标的位置

输入必须已经从小到大排好。在 [2, 4, 4, 7, 9] 中找目标 4，如果只在遇到第一个 4 时停下，可能返回第二个 4。下面的左边界查找（lower bound）继续向左缩小范围，返回第一个 ≥ target 的位置。

我们始终维护左闭右开区间 [left, right)：包括 left，不包括 right。初始为 [0, 5)，所以 right 可以等于数组长度 5，它并不是一个可读取的元素下标。图中的数字下面一行是下标；划线表示已排除，深色表示本轮的中点 mid。

同一过程的状态表：先计算 mid，再更新边界
轮次[left, right)mid / nums[mid]比较与动作
1[0, 5)2 / 44 ≥ 4，right = 2
2[0, 2)1 / 44 ≥ 4，right = 1
3[0, 1)0 / 22 < 4，left = 1
结束[1, 1)不再读取元素返回下标 1

为什么可以排除一半？若 nums[mid] < target，由于数组有序，mid 及其左侧都小于目标，答案只能在 mid 的右边，所以令 left = mid + 1。否则 mid 可能就是答案，或答案还在更左边；令 right = mid，保留它作为候选边界。整个过程中，left 左侧的值都小于目标，right 及其右侧的值都不小于目标。两者相遇时，边界就唯一确定了。

def lower_bound(nums, target):
    left, right = 0, len(nums)
    while left < right:
        mid = (left + right) // 2
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid
    return left

调用 lower_bound([2, 4, 4, 7, 9], 4) 返回 1。每轮区间约减半，时间 O(log n)，额外空间 O(1)。这份实现返回的是插入位置，不保证该处一定等于目标：查找 5 返回 3（指向 7），查找 10 返回 n = 5（应插到末尾，不能读取 nums[5]）；空数组返回 0。需要判断是否真的找到时，先确认 pos < len(nums)，再检查 nums[pos] == target。

二分还可以找什么？

  • 普通二分：在有序数组中找任意一个等于目标的元素。比较中点后缩小范围，相等就返回；O(log n) 时间、迭代版 O(1) 额外空间。重复值存在时，它不保证返回最左或最右那个。
  • 左右边界：左边界找第一个 ≥ 目标的位置；右侧插入边界找第一个 > 目标的位置。把两者相减可统计目标出现次数。例如两个 4 的范围为 [1, 3)，共 2 个，最右相等下标是 2。每次边界查找 O(log n)，有序输入仍是前提。
  • 二分答案：如“按顺序运送一批包裹，D 天内送完需要的最小载重”，在可能的载重范围上二分，每次模拟能否按时完成。关键前提是可行性随载重单调变化：某载重能完成，更大的也能完成。若答案候选范围大小为 R、一次判定扫描 n 个包裹，总时间 O(n log R)；没有这种单调关系，就不能照搬二分。

从用途认识哈希、指针、栈和队列

选工具时先说清楚“保存什么信息、下一步做什么”。下面每个小例子都能手算；它们的使用条件比记住名称更重要。

  • 哈希映射（HashMap）与哈希集合（HashSet）：处理 ["猫", "狗", "猫"]，集合只记录“见过谁”，结果为猫、狗；映射保存“键 → 值”，可以计数得到猫 2 次、狗 1 次。元素或键需要可散列。查询、插入平均 O(1) 依赖散列分布与冲突处理，不是无条件保证；冲突严重时单次可能退化到 O(n)。遍历 n 个值计数平均 O(n)，存储成本随不同键的数量增长。
  • 滑动窗口：在字符串 "abca" 中找最长无重复连续片段，右端加入字符，同时维护字符计数；最后一个 a 造成重复，就从左端移出第一个 a，窗口变成 "bca"。窗口条件必须能随加入、移出而更新，并能判断何时收缩；若每个元素最多进出一次且更新平均 O(1)，总时间 O(n)，空间随窗口内的不同元素数增长。求“和不超过某值的最长子数组”时，常见直接收缩法需要非负数，遇到负数不能直接套用。
  • 快慢指针：用于链表判环时，slow 每次沿 next 走一步，fast 走两步；若有环，快指针会在环内追上慢指针。若 fast 或它的下一节点为空，就到达结尾，说明无环。判断比较的是同一个节点，而不是节点里的值。在可达节点数为 n 时，时间 O(n)、额外空间 O(1)；每次走两步之前都要检查空节点。
  • 单调栈：找每个值右侧第一个更大值，可以把“还没找到答案”的下标放进栈，栈内对应的值保持单调。新值到来时，不断弹出比它小的栈顶，并把它们的答案设为新值，最后把新值的下标入栈。对 [2, 1, 3]，3 先解决 1，再解决 2，结果为 [3, 3, 无]。找严格更大时，相等不能当成答案。每个下标各入栈、出栈至多一次，总时间 O(n)、额外空间 O(n)。
  • 队列与广度优先搜索（BFS）：队列按先进先出（FIFO）取元素。若 A 的邻居是 B、C，先取出 A，再把 B、C 加到队尾，就会先处理这两个一跳邻居，再处理更远的节点；这是 BFS 按层扩展的原因。一般图需要在入队时标记已访问，避免重复入队。使用两端队列可让每次入队、出队为 O(1)；从 Python 列表头部删除元素会搬移其余元素，单次为 O(n)。图遍历成本取决于可达顶点 V 和边 E，使用邻接表时为 O(V + E)，访问记录及队列需要 O(V) 空间；最少边数等于最短路只适用于无权或等权图。

动手检查：把快排输入改成 [3, 3, 1]，先写出三组；把二分目标改成 5，确认返回的是 7 所在的位置；再用 [2, 1, 3] 逐步写下单调栈的入栈和弹栈。能说清“哪些值已经排除、哪些值仍待处理”，比只背复杂度更接近掌握。
