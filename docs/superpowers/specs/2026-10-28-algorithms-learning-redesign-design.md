# 算法地图入门内容与图示改版设计

## 目标

将算法地图改成适合编程入门者阅读的学习材料。读者应能跟着具体输入逐步看懂算法状态如何变化、每一步为何成立，以及算法适用于什么场景。

## 范围

改版 `algorithms/` 下的全部 7 个页面：总览、基础算法、数据结构、算法思想、工程算法、AI 时代算法和学习路线。

- 保留现有 URL、站点布局和返回导航。
- 保留 Python 作为代码示例语言。
- 重做每个页面现有的 SVG 图；为目前只有概念清单、缺少关键过程图的主题补充图示。
- 不增加 JavaScript 交互、第三方图库或外部资源依赖；排序动图使用仓库内的 GIF 文件。
- 图示生成脚本放入 `tools/algorithms/`，其余改动限于算法地图与对应样式。

## 页面设计

### 总览

说明“问题形状如何帮助选择算法工具”，用有方向的图连接基础算法、数据结构、算法思想、工程应用和 AI 检索。各节点链接到对应专题页，图中术语与正文一致。

### 基础算法

- 快速排序：以 `[5, 2, 3, 1, 4]` 制作 GIF，展示选中间位置基准、按顺序扫描分区、递归基线与最终拼接。图示和代码都使用显式循环创建分区列表，并说明不是原地交换。
- 二分查找：用含重复值的有序数组逐步展示左闭右开区间如何缩小，以及 `lower_bound` 返回什么。
- 哈希、双指针、栈和队列：分别说明适合解决的问题、使用前提和常见边界，不只列出名称。
- 明确前提：二分查找要求有序输入；双指针要说明左右指针各自维护的条件；哈希查找的平均复杂度不能写成无条件保证。

### 数据结构

- 链表反转：连续展示 `prev`、`cur`、`next` 的变化，标出每次断开和重连的指针。
- BFS：对小型图逐步显示队列、已访问集合和当前节点，区分遍历顺序与层数。
- 树与图的其余条目补充关键操作、适用场景和必要前提，例如 BFS 无权最短路、Dijkstra 非负边权限制。

### 算法思想

- 动态规划：以爬楼梯为例列出状态定义、转移关系和逐项计算结果。
- 回溯：用排列或组合展示选择、递归、撤销选择的搜索分支。
- 贪心：说明局部选择何时能导出全局最优，并给出需要证明或不适用的情形。

### 工程算法

- LRU：展示访问后顺序变化，以及容量已满时淘汰哪个条目。
- 一致性哈希：展示节点与键在环上的位置，并说明新增节点时哪些键需要迁移。
- 布隆过滤器等条目说明适用目的、资源取舍和误判边界。

### AI 时代算法

- 向量检索：从文本向量、相似度计算到 Top-K 结果逐步展示；解释精确检索与 ANN 的速度、召回取舍。
- Transformer：用简化的小例子解释 token 之间如何产生注意力权重，以及加权结果表示什么。
- 机器学习条目说明目标、输入输出和适用场景，避免只罗列模型名。

### 学习路线

把阶段、先修关系和检查点连接起来。每一阶段给出少量可观察的掌握标准，帮助读者判断是否进入下一阶段。

## 专题讲解结构

每个专题中的算法条目至少交代：它解决什么问题、成立所需的输入条件、关键步骤、复杂度和常见边界。核心算法使用完整的逐步演算示例：

1. 给出具体问题和输入。
2. 用图或状态表逐步跟踪关键状态。
3. 解释每一步的依据，以及重要不变量或正确性直觉。
4. 给出与演算完全对应的 Python 实现和输出。
5. 说明时间与空间复杂度、适用场景、局限和易错边界。

复杂度必须与页面展示的实现一致。例如，使用额外列表的快速排序实现不能描述成原地排序；二分查找需明确数组有序及区间定义。

## 图示规范

- 排序使用由实际算法轨迹生成的 GIF，显示当前输入、基准、三个分区、递归调用和中文步骤说明。末帧停留后再循环，并明确“重新演示”。GIF 文件放在 `algorithms/assets/`，提供可重复生成的脚本。
- GIF 同时配有文字步骤和静态过程说明，便于读者停下来阅读。
- 使用内嵌 SVG 的多步状态图，每一步使用相同示例数据，并标出变量、队列、指针或候选区间。
- 颜色表达状态变化时同时配文字或形状标记，不能只靠颜色传达信息。
- 图示包含简短标题和图注；为 SVG 提供可访问名称及必要描述。
- 在窄屏宽度下保持文字可读，允许步骤上下排列，不裁掉关键标签。
- 每页优先深入解释少量代表性算法；其余列表条目也需要明确用途和边界，但不要求每个名称都配一张完整流程图。

## 验收标准

- 7 个页面均完成文案和图示改版，现有链接及 URL 保持可用。
- 六个专题页各至少有一组可跟随的具体演算；图中步骤与相邻说明、示例代码一致。
- 入门读者可以从图中辨认关键状态变化，并从文字中理解算法适用条件和结果。
- 关键条目不再只给结论或术语列表；复杂度、输入假设和代表性边界明确。
- 页面不依赖新脚本或外部图库，SVG 在桌面和窄屏布局中完整可读。

## 验证

- 运行 `bundle exec jekyll build`，检查 7 个页面均进入生成目录且 Jekyll 模板链接正确渲染。
- 检查每个演算示例的输入、逐步状态、输出、代码和复杂度相互一致。
- GIF 生成时验证分区关系、递归结果和停止条件，并解码成品检查帧内容、循环标记和时长。
- 使用 `git diff --check` 检查改动格式，并在浏览器中查看桌面与窄屏下的图示和正文。
