# 小游戏区与《青衫问路》接入设计

## 目标

将站点现有的“棋局大厅”扩展为统一的“小游戏区”，使访问者能从首页进入小游戏入口，并打开网页 RPG《青衫问路》。部署到 GitHub Pages 和本地 Jekyll 服务时，RPG 的静态资源都必须正确加载。

## 范围

- 首页入口由“棋局大厅”更名为“小游戏区”，链接仍指向 `/board-room/`。
- `board-room/` 继续承载五子棋和三炮十五兵，并在玩法选择列表中加入《青衫问路》。新卡片跳转至 `/青衫问路/`。
- 修正 `青衫问路/index.html` 的 JavaScript 和 CSS 引用，使其相对于 RPG 目录加载 `assets/` 下的构建产物。
- 不修改 RPG 的玩法、资源、构建产物、棋类游戏逻辑或视觉主题。

## 页面与数据流

1. 访问首页时，用户看到“小游戏区”卡片，点击“进入小游戏区”。
2. 浏览器进入 `/board-room/`，该页面展示三种玩法：五子棋、三炮十五兵和《青衫问路》。
3. 前两项继续由现有 JavaScript 在同页启动；《青衫问路》使用普通链接跳转至 `/青衫问路/`。
4. RPG 页面从同目录的 `assets/` 加载 CSS、JavaScript、图片和音频资源，初始化其既有游戏根节点。

## 错误处理与兼容性

- RPG 静态资源使用相对路径，避免根路径 `/assets/` 在该站点中指向不存在的位置。
- 新入口使用语义化链接，浏览器在 JavaScript 不可用时仍能导航至 RPG 页面。
- 沿用棋局大厅的现有交互和样式，避免影响两种棋类玩法。

## 验证

- 运行 `bundle exec jekyll build`，确认站点可构建。
- 检查生成后的首页卡片、小游戏区入口以及 RPG 的 CSS/JavaScript 资源引用路径。
- 本地启动后，访问首页、小游戏区和 `/青衫问路/`，确认三条导航链路可用。
